# Decision Log Convention

에이전트가 작업을 끝낼 때, **주고받은 질문과 내린 결정을 기록으로 남깁니다.**

코드와 커밋 메시지는 "무엇을 만들었는지"를 말하지만 "무엇을 물었고, 무엇을 답 없이 스스로 정했고,
어디를 되돌릴 수 있는지"는 말하지 않습니다. 이 기록은 그 자리를 메워서, 요청한 사람이 기능을
받아들일지 판단할 수 있게 합니다.

## 언제 남기는가

**필수** — 아래 중 하나에 해당하면 남깁니다.

- 도구를 추가·변경했다 (`src/tools/`의 `name`은 공개 계약이라 배포 후 되돌릴 수 없습니다)
- 의존성을 추가·제거·버전 변경했다
- 빌드·릴리스 설정(`tsup.config.ts`, `package.json`, `release-please*`)을 건드렸다
- 문서가 정해 주지 않은 설계 선택을 했다 (자료 구조, 기본값, 실패 처리 방식 등)
- 물어본 것에 답을 받지 못한 채 가정을 세우고 진행했다

**생략** — 포매팅, 오타, 문서 미러 동기화, 기록된 결정을 그대로 따른 후속 작업.

## 어디에 남기는가

```
.claude/decisions/YYYY-MM-DD-<slug>.md
```

- 작업(브랜치) 하나에 파일 하나. 한 파일에 몰아 쓰지 않습니다 — 여러 작업이 병렬로 돌아가면
  같은 파일을 고쳐 충돌합니다.
- `<slug>`은 브랜치 이름이나 기능 이름을 `kebab-case`로 씁니다.
- `docs/`에 두지 않습니다. `docs/`는 배포되는 문서 사이트이고 `ko` 미러를 함께 유지해야 합니다.
  이 기록은 저장소 안에서만 읽는 작업 기록이라 **한국어로 한 번만** 씁니다.
- 기능 커밋과 **같은 커밋**에 포함합니다. 나중에 따로 올리면 빠집니다.

## 무엇을 남기는가

아래 여섯 항목을 순서대로 씁니다. 해당 없는 항목은 "없습니다"라고 적고 지우지 않습니다.

| 항목 | 쓸 내용 |
|---|---|
| 1. 요청 | 받은 요청을 요약. 도중에 요청이 바뀌었으면 바뀐 시점과 내용 |
| 2. 주고받은 질문 | 에이전트가 물은 것과 받은 답. **답을 받지 못한 질문은 반드시 표시** |
| 3. 스스로 내린 결정 | 묻지 않고 정한 것. 각 항목에 근거와 "뒤집으면 무엇이 바뀌는지" |
| 4. 판단이 필요한 지점 | 요청한 사람이 골라야 하는 것. 되돌리기 비용이 큰 것을 먼저 |
| 5. 하지 않은 것 | 범위에서 뺀 것과 그 이유. 발견했지만 고치지 않은 문제 |
| 6. 검증 결과 | 실제로 돌린 명령과 그 결과. 숫자는 측정값을 그대로 |

## 작성 규칙

- **사실만 씁니다.** 돌려 보지 않은 것을 통과했다고 쓰지 않습니다. 건너뛴 검증은 건너뛰었다고 씁니다.
- **근거를 값으로 씁니다.** "더 정확해서"가 아니라 "이 기계에서 `used`는 95%, `active`는 70.8%로
  나와서"처럼 씁니다.
- **되돌리는 방법을 같이 씁니다.** 어느 파일 어느 줄을 고치면 되는지 적습니다.
- 답을 받지 못한 질문에 세운 가정은 3번이 아니라 **2번에 남겨** 물었다는 사실이 지워지지 않게 합니다.
- 06-copywriting-rules를 따릅니다 — 강조·마케팅 표현과 이모지를 쓰지 않습니다.
